# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Tooling to turn an unstructured WhatsApp export from an operations team (solar/electrical
installation technicians) into structured tables: who worked on what project, which day, how
many hours, and how that compares to what was actually planned. The source of truth is
`chat_ws_operaciones_2026.md`, a raw WhatsApp chat export (~13k lines, one message per line,
multi-line messages continue on following lines with no marker). Everything else is derived
from it on demand — nothing here is a database, the CSV outputs are regenerated by re-running
the script, not hand-maintained.

This started as a single extraction script and is meant to grow into a full application (API +
frontend + dashboard) on top of the same extraction logic. When that build-out starts, update
this file's Architecture section to reflect the new layers — don't let it drift.

## Commands

Run from this directory (no virtualenv/dependencies — stdlib only, Python 3.14 confirmed working):

```
python extraer_horas.py
python extraer_horas.py --desde 01/03/2026 --hasta 31/03/2026
python extraer_horas.py --tecnico Guillermo --proyecto Octopus
python extraer_horas.py --output tabla_marzo.csv --desde 01/03/2026 --hasta 31/03/2026
python extraer_horas.py --sin-diagnosticos   # omite los CSV de diagnostico
```

Flags: `--input`, `--output`, `--output-asignaciones`, `--alias`, `--desde`/`--hasta` (DD/MM/AAAA),
`--tecnico`, `--proyecto` (substring filters, applied to `proyecto_final`).

No test suite exists yet. Validate changes by re-running the script and checking the printed
summary (row counts, hours-per-technician) and the diagnostic CSVs for regressions, plus spot
Grep-checking specific lines in `chat_ws_operaciones_2026.md` against the produced rows.

## Architecture

```
chat_ws_operaciones_2026.md
        │
        ▼
  chat_utils.py   — parsear_mensajes(): splits the raw export into message dicts
                     {fecha, hora, remitente, texto, linea}. cargar_alias(): loads/
                     seeds aliases.json and compiles it into (regex, canonical_name)
                     pairs, longest alias first. encontrar_tecnicos(): finds
                     non-overlapping technician mentions in a text blob (longer alias
                     "claims" its span so a shorter overlapping one, e.g. "jose"
                     inside "jose manuel", can't re-match it).
        │
        ├──▶ extraer_horas.py   — finds "hour report" messages (Imputación/Reporte de
        │                          horas), extracts (fecha, tecnico, horas, horas_extra,
        │                          proyecto) per technician mentioned. Writes
        │                          tabla_horas.csv. This is the main entry point / CLI.
        │
        └──▶ asignaciones.py    — finds "PROGRAMACION <día>" messages, parses their
                                   "EQUIPO N tecnico1/tecnico2 + proyecto" blocks
                                   (the planned assignment for the next day, usually
                                   posted the night before). Writes tabla_asignaciones.csv.

extraer_horas.py then cross-references its own rows against asignaciones.py's output
(cruzar_con_programacion) to add, per hour-report row:
  - estado_programacion: programado | no_programado (imprevisto) | sin_programacion_dia
  - equipo_programado
  - proyecto_final / proyecto_fuente (explicito | inferido_programacion | sin_dato) —
    backfills proyecto from the plan when the hour-report message didn't state one
```

`aliases.json` is the editable nickname → canonical-technician-name dictionary (auto-created
from a seed in `chat_utils.py` if missing). It's shared by both extractors, so a nickname added
here improves both hour recognition and team-assignment recognition. Keep it in sync manually —
`chat_utils.DEFAULT_ALIASES_SEED` and `aliases.json` are two copies (the seed only writes itself
if the file doesn't exist yet, it never overwrites an existing `aliases.json`).

## Why the extraction is heuristic, not exact

The chat has no fixed format — it's how ~15 different people happen to type. This has concrete
consequences worth knowing before "fixing" something that looks wrong:

- **Hour reports** use several unrelated phrasings ("Imputación de horas: Nombre N horas",
  "N horas Nombre", Demetrio's "Reporte de horas: Nombre <descripción larga> (N horas)"), with
  typo'd nicknames ("cristian/christian/crisitian/...", "sherifo/sheriff/zherifo/..."). A large
  chunk of real hour reports exist **only as an attached image** ("imagen omitida" in the
  export) — there is no way to recover those from text; they land in `sin_datos_imagen.csv`.
- **Technician recognition** is alias-based, not NLP/fuzzy — a name not in `aliases.json` simply
  won't be found. `sin_reconocer.csv` (hour messages with no recognized technician) and the
  `no_reconocidos_prog` warning (nicknames seen inside a team line, but not the whole line, that
  didn't resolve) exist specifically to surface these gaps so you can extend `aliases.json`.
- **Project inference** only trusts an explicit "proyecto" mention or Demetrio's
  client/gestoria-description format in the hour-report message itself; it does not guess by
  matching against nearby conversation. The plan-based backfill (`proyecto_fuente =
  inferido_programacion`) is the one exception, and it's explicitly labeled as inferred.
- **Programming-message dates** aren't always explicit or correct (typo'd years, day names with
  no date, Catalan day names, messages sent the same morning instead of the night before).
  `resolver_fecha_programacion` in `asignaciones.py` tries explicit date → weekday name → "night
  before" fallback, in that order — see its docstring before changing the priority.
- **EQUIPO block parsing** (`asignaciones.py: parsear_bloques_equipo`) decides "is this line a
  list of technicians or something else (address/instructions/project name)?" by checking
  whether every token on the line has name-like shape (`NOMBRE_TOKEN_RE`) and resolves via
  aliases. A partially-resolved line (one unknown nickname mixed with known ones) still keeps
  the known technicians — it doesn't discard the whole line. WhatsApp bold markup (`*...*`)
  around EQUIPO lines is stripped before matching; don't remove that stripping.

When something looks miscounted, check the relevant diagnostic CSV first — it's usually a
missing alias or an image-only report, not a parsing bug.

## Output files (regenerated, not source data)

`tabla_horas.csv`, `tabla_asignaciones.csv`, `sin_reconocer.csv`, `sin_datos_imagen.csv`,
`planificado_sin_horas.csv` are all produced by `extraer_horas.py` and safe to delete/regenerate
at any time. `aliases.json` is the one generated file that's actually hand-maintained — treat
edits to it as real changes, not disposable output.
